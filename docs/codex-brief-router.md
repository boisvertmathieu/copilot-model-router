# Brief Codex — POC du router (tout en français francophone)
Repo existant (lis README.md, scripts/registry_lib.py, scripts/select_model.py, models.yaml, tests/). NE DUPLIQUE PAS la logique de sélection: importe-la.
Construis:
1. scripts/route.py appelé par l'orchestrateur avant chaque équipier. Étage 1 classification `trivial|standard|complexe|critique`:
 - heuristique (défaut, zéro coût): signaux --diff-stats (ex "12 files changed, 340 insertions(+), 80 deletions(-)" ou fichier), --files N, --story (texte ou @fichier, mots-clés: sécurité, auth, paiement, migration, concurrence → critique; refactor, architecture, multi-modules → complexe; typo, doc, renommage → trivial), --story-type bug|feature|refactor|doc|spike. Règles simples, documentées, explicables (raison listée).
 - --classifier llm: client abstrait injecté (interface classify(prompt)->str), implémentation CopilotCliClient qui exécute `copilot --model <modèle economy choisi par le registre> -p "..."` (subprocess, timeout, parsing strict d'un seul mot; repli heuristique si échec), et FakeClient pour tests. Non validé contre vrai Copilot.
 Étage 2: mapping niveau→tier (trivial→economy, standard→standard, complexe→premium, critique→frontier, ajusté par rôle: doc plafonné standard, e2e-validator ≥ premium sauf si trivial…) puis appel à la logique existante de select_model (budget --max-cost/--budget-profile code 2, famille différente --dev-model/--dev-family code 3, --available fichier/liste/ou `--available live` qui appelle list_copilot_models.py).
 Sortie lisible par défaut; --json: {model, level, family, reason, herdr_cmd} (+ champs utiles en extra OK) avec herdr_cmd = `herdr agent start <role> --kind copilot --pane <n> -- --model <id>` (--pane, --name optionnels; quoting shlex).
2. Mode serveur: `route.py --serve` JSON-RPC 2.0 sur stdio, une requête JSON par ligne (méthodes route, ping, reload), registre chargé une fois. Documente le protocole dans docs/router.md.
3. Tier provisoire: dans sync_registry, un modèle nouveau sans tier connu reçoit un tier déduit (catégorie+prix) avec `tier_provisoire: true` et note « à valider »; le router l'accepte mais l'indique dans reason/warnings. Teste-le.
4. Mise à jour auto: scripts/refresh.sh (list_copilot_models si dispo → sync_registry --from-cli-models; sinon sync seule), Makefile (test, refresh, route-demo), exemples cron et ~/.bashrc au login WSL (avec garde 1x/jour) dans docs/router.md.
5. Tests unittest stdlib: chaque niveau heuristique, client LLM fake + repli sur échec, contrainte famille (code 3), budget (code 2), format herdr_cmd, mode serveur (sous-processus, plusieurs requêtes), tier provisoire. Tous les anciens tests doivent passer.
6. docs/router-proof.md: exécute RÉELLEMENT des scénarios bout-en-bout (petit bug doc→trivial→economy; gros refactor multi-fichiers→complexe→premium; critique sécurité; validateur e2e avec dev=claude-sonnet-5.5→autre famille; budget serré→repli; budget impossible→code 2; famille impossible→code 3; serveur stdio avec 2 requêtes; classifier llm avec faux client) et colle entrées+sorties réelles et codes de sortie.
7. docs/herdr-integration.md: ajoute un exemple bash d'orchestrateur: pour chaque équipier, appeler route.py --json (ou le serveur), lire herdr_cmd avec jq/python, exécuter, puis passer la famille du dev au validateur.
8. Mets à jour README.md et .github/copilot-instructions.md (invocation du router). Sois honnête: pas d'org Copilot ni Herdr ici; classif LLM et /models live à valider sur le poste de travail.
