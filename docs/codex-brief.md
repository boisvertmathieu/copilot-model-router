# Brief pour Codex
Contexte: un agent orchestrateur multi-agents lance des équipiers (dev, test, doc, validateur e2e, revue...) comme sessions GitHub Copilot CLI via Herdr dans WSL. Problème: tous utilisent le même modèle. On veut choisir le modèle par rôle selon un niveau de perf (economy|standard|premium|frontier) OU un budget de coût, et le validateur e2e doit être d'une FAMILLE (fournisseur) différente du dev.

Faits VÉRIFIÉS (oct. 2026):
- Depuis le 1er juin 2026 Copilot = facturation à l'usage en "GitHub AI Credits" (1 crédit = 0,01 $ US), prix par 1M tokens par modèle. Source: https://docs.github.com/en/copilot/reference/copilot-billing/models-and-pricing
- Données machine-lisibles officielles: https://raw.githubusercontent.com/github/docs/main/data/tables/copilot/models-and-pricing.yml (copie dans upstream/), aussi model-comparison.yml, model-supported-clients.yml (champ cli: true/false), annual-subscriber-model-multipliers.yml (multiplicateurs LEGACY, seulement pour plans annuels Pro/Pro+ restés sur l'ancien modèle).
- Copilot CLI: `copilot --model <ID> -p "..."`, `/model` interactif, `/config model`, `--model fusion --fusion-tier standard|high|max` (auto-sélection), `/limits set max-ai-credits N`. Le Copilot SDK a `listModels()` (méthode RPC models.list) qui renvoie id, capabilities, billing, policy, reasoning efforts.
- Herdr: `herdr agent start <nom> --kind copilot --pane <pane> -- <args passés tels quels à copilot>` donc `-- --model <ID>` marche.
